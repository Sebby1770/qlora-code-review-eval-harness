Guide

Four steps. No model required.

  1. 1. An exam, not a prompt

    A golden set is a list of code diffs with the comment a careful reviewer would write, plus a few phrases that comment must mention.

  2. 2. The bot’s answers

    Predictions are those comments. If you do not have a model, Studio uses a built-in baseline that only looks at keywords in the diff.

  3. 3. A letter grade, in English

    We do not require word-for-word match. We ask: did it mention the required facts, avoid banned nits, and get the seriousness right?

  4. 4. Open the worst example first

    The inspector shows the diff, the expected comment, what the bot wrote, and which required phrases it skipped.

How scoring works

Plain language first, then the formula.

The overall number

Exact string match is too brittle for review comments, so Studio mixes several signals. Required phrases carry more weight than word overlap, because catching the bug matters more than sounding like the reference sentence.

What “must mention” actually does

We lowercase the comment, turn punctuation into spaces, and ask whether each required phrase appears as a substring. “Expired refresh tokens” matches “this no longer rejects expired refresh tokens”. It will not match a clever paraphrase that never uses those words — that is a known limit, not a secret.
